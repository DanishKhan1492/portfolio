01 About

The engineer you call
when it has to hold.

I build the parts of a system that nobody sees at the demo: the services that stay correct under load, the pipelines that make a release boring, the migrations that happen without a war room.

My core stack is Java: Spring Framework, Spring Boot, Spring Data, Hibernate and JPA. REST APIs and microservices are the default shape, with Kafka, Redis and Liquibase carrying events, state and schema change. Around it I run Go for services that need a small footprint and a fast start, plus Python and Bash for the automation that removes people from the loop.

For the last five years the delivery side has mattered as much as the code: Docker, Kubernetes and Helm charts, with CI/CD in GitHub Actions. On AWS I have worked with Lambda, and with Amazon Connect and Lex to prototype a conversational-AI call centre. Before cloud-native took over, I spent years automating enterprise operations with Blue Prism and Automation Anywhere RPA.

I am happiest in the awkward middle: a client's unfamiliar framework, a legacy Java EE monolith, a half-finished migration. The job is to learn it, stabilise it, then hand the team something better than what was there before.

  • Own whole epics. Several at a time, from design review through implementation to a deployment that sticks, including the cross-functional coordination nobody else wants.
  • Teach what you learn. Adopting an unfamiliar framework only counts once the rest of the team can build on it confidently.
  • Make the machine do it. Deployment, migration, monitoring and coverage are scripts and pipelines, not rituals performed by hand.
  • Leave a readable codebase. Memory leaks, bugs and code smells get fixed as part of the work, not filed as someone else's ticket.
